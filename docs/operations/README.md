# 운영·데이터 처리 한계

[메인 README](../../README.md)

## 현재 운영 형태

저장소에는 CI workflow, Docker, 클라우드 배포, 인증, 관계형 운영 DB 설정이 확인되지 않았습니다. API는 로컬 FastAPI, 프런트엔드는 Vite 개발 서버 중심이며, ChromaDB는 로컬 파일 저장소를 사용합니다.

공고의 SAMPLE_JDS 레지스트리는 메모리 기반입니다. 스크랩한 공고가 프로세스 메모리에서 관리되므로 운영 서비스의 영구 공고 DB로 간주할 수 없습니다.

## 개인정보와 채용 판단

이력서 PDF의 텍스트는 설정된 외부 LLM 제공자에 전송될 수 있습니다. 실제 지원자 자료를 넣기 전에 고지·동의, 데이터 최소화, 저장·삭제 기간, 외부 제공자 정책을 확인해야 합니다. 공개 데모에서는 가명·샘플 자료를 사용하세요.

매칭 점수는 PoC의 휴리스틱과 LLM 출력이며 채용 결정의 객관적 정답을 보장하지 않습니다. 채용 담당자가 원문과 기준을 검토하는 보조 정보로 표시해야 합니다.

## 운영 이전 전 필요한 작업

- 제공자 설정을 명시적인 OPENAI_API_KEY와 GEMINI_API_KEY로 분리하고 기능별 폴백 동작 검증
- 지원자·채용 공고용 영속 DB, 데이터 삭제와 접근 권한 정책 구현
- 파일 업로드 제한, 악성 파일 검사, 임시파일 삭제와 개인정보 암호화
- 스크래퍼의 사이트 정책·요청 속도·오류 재시도·공고 최신성 처리
- API 인증·CORS·로그에서 이력서 원문 제거
- 단위·API·브라우저 테스트 및 GitHub Actions CI 구성
- 배포 환경, 모니터링, 비밀값 저장과 백업 계획 수립
